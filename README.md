# План автоматизации тестирования сценария перехода к форме записи и заполнения формы
## 1. Перечень автоматизируемых сценариев

### 1. Позитивные сценарии:

#### Сценарий 1. Переход к форме записи через раздел «Каталог курсов» → «Программирование»

##### * Шаги:
  
  * Открыть главную страницу сайта Netology.
  * В шапке сайта нажать кнопку «Каталог курсов».
  * В открывшемся меню выбрать направление «Программирование».
  * В списке курсов найти и кликнуть на курс «Инженер по тестированию».
  * Прокрутить страницу курса до формы записи.

##### * Ожидаемый результат: Отображается форма записи с полями «Имя», «Телефон», «Электронная почта», кнопками «Записаться» и «Получить консультацию», а также чекбоксами согласия.

#### Сценарий 2. Переход к форме записи через поиск в каталоге курсов
##### * Шаги:

 * Открыть главную страницу сайта Netology.
 * Нажать «Каталог курсов».
 * В поле поиска «Какой курс вам нужен?» ввести «Инженер по тестированию».
 * Нажать кнопку «Найти курс» (или клавишу Enter).
 * В результатах поиска кликнуть на курс «Инженер по тестированию».
 * Прокрутить страницу до формы записи.
##### * Ожидаемый результат: Отображается форма записи, соответствующая курсу «Инженер по тестированию».

#### Сценарий 3. Переход к форме записи через главную страницу (кнопка «Записаться» на странице профессии)
##### * Шаги:

* Открыть главную страницу сайта Netology.
* В блоке направлений обучения выбрать «Программирование».
* Перейти на страницу курса «Инженер по тестированию».
* Нажать кнопку «Записаться» (если доступна на странице).
* Убедиться, что произошёл скролл к форме записи.
##### * Ожидаемый результат: Форма записи отображается в видимой области экрана.

#### Сценарий 4. Заполнение формы валидными данными (позитивный)
##### * Входные данные:

* Имя: строка на кириллице, от 2 до 50 символов, например: «Иванов Иван».

* Телефон: российский номер в формате +7 (XXX) XXX-XX-XX, например: «+7 (999) 123-45-67».

* Email: корректный адрес, например: «test.user@example.com».

* Чекбокс согласия на обработку персональных данных — активирован.

##### * Шаги:

* Заполнить поле «Имя» валидным значением.
* аполнить поле «Телефон» валидным значением.
* Заполнить поле «Электронная почта» валидным значением.
* Активировать чекбокс согласия на обработку персональных данных.
##### * Ожидаемый результат: Все поля заполнены, чекбокс активен, кнопка «Записаться» доступна для нажатия (не заблокирована).

#### Сценарий 5. Заполнение формы невалидным именем (негативный, отдельный сценарий)
##### * Входные данные:

* Имя: «Иван123!@#» (содержит цифры и спецсимволы).

* Телефон: валидный.

* Email: валидный.

##### * Шаги: Заполнить поле «Имя» невалидным значением, остальные поля — валидными.

##### * Ожидаемый результат: Под полем «Имя» появляется сообщение об ошибке валидации; кнопка «Записаться» недоступна.

#### Сценарий 6. Заполнение формы невалидным телефоном (негативный, отдельный сценарий)
##### Входные данные:

* Телефон: «12345» (не соответствует маске).

* Имя: валидное.

* Email: валидный.

##### Шаги: Заполнить поле «Телефон» невалидным значением, остальные — валидными.

##### Ожидаемый результат: Под полем «Телефон» появляется сообщение об ошибке; кнопка «Записаться» недоступна.

#### Сценарий 7. Заполнение формы невалидным email (негативный, отдельный сценарий)
##### * Входные данные:

* Email: «test@test» (без доменной зоны) или «test.test.com» (без @).

* Имя: валидное.

* Телефон: валидный.

##### * Шаги: Заполнить поле «Электронная почта» невалидным значением, остальные — валидными.
##### * Ожидаемый результат: Под полем «Электронная почта» появляется сообщение об ошибке; кнопка «Записаться» недоступна.

#### Сценарий 8. Отправка формы с пустыми обязательными полями (негативный)
##### * Входные данные: все поля пустые.

##### * Шаги: Оставить все поля пустыми, попытаться нажать «Записаться».
##### * Ожидаемый результат: Кнопка «Записаться» недоступна или появляются сообщения об обязательности заполнения полей.

#### Сценарий 9. Отправка формы без согласия на обработку персональных данных (негативный)
##### * Входные данные: все поля валидные, чекбокс согласия не активирован.
##### * Шаги: Заполнить поля валидными данными, не активировать чекбокс, нажать «Записаться».
##### * Ожидаемый результат: Кнопка «Записаться» недоступна или появляется предупреждение о необходимости согласия.

#### Сценарий 10. Проверка максимальной длины полей (граничный)
##### * Входные данные:

* Имя: строка из 50 символов (или максимально допустимая по спецификации).

* Телефон: максимально допустимая длина.

* Email: максимально допустимая длина.

##### * Шаги: Заполнить поля значениями максимальной длины.

##### * Ожидаемый результат: Данные принимаются, валидация проходит успешно, кнопка «Записаться» доступна.


### 2. Перечень используемых инструментов с обоснованием выбора

Инструмент | Обоснование выбора
:----------|:-------------------:
Java 11+ | Кроссплатформенный язык, обширная экосистема библиотек для тестирования.
JUnit 5	| Современный фреймворк для написания и организации тестов, поддержка параметризации и параллельного запуска.
Selenide| Упрощает работу с Selenium WebDriver: автоматические ожидания, лаконичный синтаксис, удобные селекторы.
Allure	| Формирование наглядных отчётов, интеграция с CI/CD, поддержка вложений и шагов.
Gradle	| Управление зависимостями, сборка и запуск тестов, гибкая конфигурация.
Faker	| Генерация реалистичных тестовых данных (имена, телефоны, email) для позитивных и негативных сценариев.
Docker	| Изоляция тестового окружения, воспроизводимость запусков.
Git	| Контроль версий тестового кода, совместная работа.

### 3. Перечень необходимых разрешений, данных и доступов
#### Разрешения:
* Письменное разрешение на автоматизированное тестирование сайта Netology (в рамках учебного задания).

* Согласование с владельцем сайта на использование тестовых данных.

#### Данные:
* Спецификация валидации полей формы: допустимые символы, длины, форматы.

* Тексты сообщений об ошибках для каждого поля.

* URL-адреса страниц: главная, каталог курсов, страница курса «Инженер по тестированию».

* Правила работы чекбоксов (обязательность, влияние на доступность кнопки).

#### Доступы:
* Доступ к репозиторию для хранения тестового кода.

* Доступ к CI/CD для автоматического запуска тестов.

* Доступ к Allure-серверу для просмотра отчётов.

### 5. Перечень необходимых специалистов для автоматизации
Для реализации данного проекта достаточно одного инженера-тестировщика-автоматизатора, обладающего следующими компетенциями:

* Опыт работы с Java, Selenide, JUnit 5, Allure.

* Понимание принципов UI-тестирования, работы с ожиданиями.

* Навыки анализа веб-страниц (DevTools, поиск селекторов).

* Знание Git, Gradle, базовое понимание CI/CD.

Дополнительные роли (DevOps, разработчики) не требуются, так как проект ограничен написанием плана и тестовых сценариев без внедрения в production-инфраструктуру.
