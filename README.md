# План автоматизации тестирования сценария перехода к форме записи и заполнения формы
## 1. Перечень автоматизируемых сценариев

### Позитивные сценарии:

#### 1 Успешный переход к форме записи на курс "Инженер по тестированию"

* Открытие главной страницы сайта

* Переход в раздел "Программирование"

* Поиск курса "Инженер по тестированию"

* Переход на страницу курса

* Проверка отображения заголовка курса

* Проверка наличия формы записи в нижней части страницы

#### 2. Успешное заполнение формы записи валидными данными

* Заполнение поля "Имя" валидным значением (кириллица)

* Заполнение поля "Телефон" валидным номером

* Заполнение поля "Email" валидным адресом

* Активация чекбокса согласия на обработку персональных данных

* Активация чекбокса подписки на новости

* Проверка активности кнопки "Записаться"

#### 3. Успешная отправка формы с валидными данными

* Заполнение всех полей валидными данными

* Активация всех обязательных чекбоксов

* Отправка формы

* Проверка появления сообщения об успешной записи

### Негативные сценарии:

#### 4. Заполнение формы с невалидными данными

* Поле "Имя" с цифрами и спецсимволами

* Поле "Телефон" с некорректным форматом

* Поле "Email" с некорректным форматом

* Проверка валидационных сообщений

#### 5. Отправка формы с пустыми обязательными полями

* Оставление поля "Имя" пустым

* Оставление поля "Телефон" пустым

* Оставление поля "Email" пустым

* Проверка валидационных сообщений

#### 6. Отправка формы без согласия на обработку данных

* Заполнение всех полей валидными данными

* Отказ от согласия на обработку данных

* Проверка блокировки кнопки "Записаться"

### Граничные сценарии:

#### 7. Проверка максимальной длины полей

* Максимальное количество символов в поле "Имя"

* *Максимальная длина номера телефона

* Максимальная длина email-адреса

### 3. Перечень необходимых разрешений, данных и доступов

#### Разрешения:
* Разрешение на автоматическое тестирование сайта

* Доступ к среде разработки/тестирования (тестовому стенду)

* Разрешение на создание тестовых пользователей

#### Данные:
* Спецификация валидных форматов полей (имя, телефон, email)

* Максимальные/минимальные допустимые значения полей

* Текст валидационных сообщений для негативных сценариев

* URL-адреса всех страниц участвующих в сценарии

* Ожидаемое поведение после успешной отправки формы

#### Доступы:
* Доступ к репозиторию с тестовым кодом

* Доступ к CI/CD системе для автоматического запуска тестов

* Доступ к системе отчетности (Allure)

### 4. Перечень и описание возможных рисков при автоматизации
#### Технические риски:
##### 1. Динамические изменения DOM-структуры

* Вероятность изменения идентификаторов и CSS-классов

* Необходимость поддержки селекторов в актуальном состоянии

##### 2. Сложность поиска элементов

* Некорректное отображение элементов на разных разрешениях экрана

* Долгая загрузка страниц и элементов

##### 3. Зависимость от сетевых условий

* Некорректная работа при медленном интернете

* Тайм-ауты при асинхронных запросах

##### 4. Сложность с тестовыми данными

* Потенциальные конфликты при использовании одинаковых тестовых данных

* Необходимость очистки данных после каждого теста

#### Организационные риски:
##### 5. Изменение требований к функциональности

* Модификация процесса записи

* Изменение обязательных полей

##### 6. Отсутствие доступа к тестовому окружению

* Невозможность выполнения тестов

* Задержки в разработке

##### 7. Недостаточная квалификация команды

* ложность с поддержкой тестового кода

* Ошибки в реализации тестов

### 5. Перечень необходимых специалистов для автоматизации
#### Ключевые роли:
##### 1. Автоматизатор тестирования (1-2 человека)

* Разработка и поддержка тестовых сценариев

* Настройка фреймворка и инфраструктуры

* Анализ результатов тестирования

#### Дополнительные роли (по необходимости):
##### 2. QA-инженер

* Участие в написании тестовых сценариев

* Проверка корректности автоматизации

##### 3. DevOps инженер

* Настройка CI/CD процесса

* Обеспечение инфраструктуры для выполнения тестов

##### 4. Разработчик (консультант)

* Консультации по структуре приложения

* Помощь в поиске стабильных селекторов
